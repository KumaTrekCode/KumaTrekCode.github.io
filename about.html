実車の計測データで筋道を立て、検証で裏を取り、良否判定まで責任を持ってつなぐ。

Introduction

仕組みを分解して理解し、情報を整理して伝えることに強みがあります。手順を決めたら抜け道を作らずに進め、完了まで責任を持つタイプです。

現在の業務は実車評価が中心です。車両の通信やECU の内部値の計測を行い、取得したデータに基づいて良否判定まで担当しています。仕様とログの両面から、説明可能な形で結論を出すことを大切にしています。

現場で培った車両・電気・化学品の素地と、計測・評価の経験が相互に補強される働き方です。

Values

大切にしていること

  • Minimalism — 思考と身の回りを単純に保ち、優先度の高いことに時間と集中を使う。
  • Logical clarity — 前提と結論をはっきりさせ、測定できる事実や記録で説明し合う。
  • Interests — 国内旅行。47都道府県を踏破するのを目標にしています。

保有スキル

資格・免許と、実務での車載計測・評価を、いまの自分の軸として整理しています。

  • 大型運転

    大型自動車免許。重量物・長尺の扱いと、車両挙動への感覚の土台

  • 自動車整備士

    二級自動車整備士。機構と故障の因果を追うときの基礎体力

  • 電気工事士

    第２種電気工事士。制御回路・電源まわりの安全と規格の素地

  • 危険物取扱

    危険物取扱者 第1〜6類。化学品の性質と保管・運用上のリスク意識

  • ECU などの計測

    車両通信や ECU 内部値の取得・整理を行い、実車評価における良否判定の根拠づくりに使っています。

今後取得・強化したいスキル

手段ではなく、仕事に接続したい能力として優先しています。Web・データ処理・Linux はいずれも Gemini 由来の tier 画像（build:icons で再生成）です。

  • Web 開発

    HTML / CSS / JavaScript。ポートフォリオや小さなツールを通じて、説明可能な形で成果を残す力を伸ばす。

  • データ処理・自動化

    Python と標準ライブラリ、pandas・可視化。ログや試験データの整形・集計から、再現可能な手順で判断までつなげ、共有しやすい形にしたい。

  • 開発・計測環境（Linux）

    Ubuntu、シェル、パッケージと権限、Git / GitHub。計測・解析・自動化のための土台を手順として固定し、CLI はその入口として扱いつつ、自分やチームが同じ構成を後から取り戻せるようにしたい。

目指している姿

長期的なゴール

  • シミュレーションから実機評価までをトータルに設計・実行し、良否判定まで一貫して担えること。上流のモデル・シミュレーションと、現車の計測・判定を同じ設計思想でつなげたいです。
  • 現時点では業務の比重が実機評価に寄っています。計測データに基づく判断の精度と説明責任を高めながら、上流との接続を少しずつ広げていく段階だと捉えています。
