## プロンプト: 1ページ分の「静的書き出し品質」チェック（最短）

保存した HTML が「そのページの静的版として成立しているか」を、最小の情報でチェックするためのプロンプトです。
AI に送るときは、必要なら `[ ]` を埋めてください。

---

あなたは静的サイトのレビュー担当です。以下の情報から、GitHub Pages 配下（サブディレクトリ）で破綻しないかを確認し、**問題点と直し方**を箇条書きで返してください。

## 入力

- 対象ページ: `[PAGE].html`（例: `menu-salad.html`）
- 公開想定パス: `projects/open-cafe-wp-export/[PAGE].html`
- 添付: `[PAGE].html` の全文
- 可能ならスクショ: 崩れている箇所（任意）

## チェック観点（優先順）

1. **読み込みパス**
   - `href/src/srcset` が **`./assets/...`** 等の相対になっているか
   - `/wp-content/` や `file://` など、環境依存の参照が残っていないか

2. **404 になりそうな参照**
   - HTML 内で参照しているファイル名が、同じフォルダー（`./`）または `./assets/` に存在しそうか

3. **ページ間リンク**
   - ナビやパンくずが `./concept.html` のように「存在する予定の HTML」を指しているか
   - まだ無いページを指す場合、どう運用するのが安全か（リンクを残す/隠す/同時に作る）

4. **canonical / og:url**
   - そのページ自身（`./[PAGE].html`）になっているか

## 出力

- 問題がある場合: **「原因 → 修正方針（HTML/CSS/アセット）→ 具体例」**
- 問題がない場合: **「このまま統合してよい」** と結論だけ短く
