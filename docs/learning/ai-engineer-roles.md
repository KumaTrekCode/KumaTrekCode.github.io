## 動画の主張（一言）

エンジニア職種は AI 普及で **17種・4層**に分化している。未経験はまず第1層で実務を積み、第2〜3層を経て第4層（AI最前線）へ進むのが現実的、というロードマップ。

## 4層の地図（要約）

| 層 | 役割 | 職種 |
|----|------|------|
| **第1層** 入り口 | 未経験から狙える王道 | バックエンド / フロントエンド / インフラ・クラウド / モバイル |
| **第2層** 土台と専門 | スキル拡張・専門化 | フルスタック / QA・SET / データエンジニア / セキュリティ / 社内SE・コーポレートIT |
| **第3層** 信頼性・基盤 | 組織・運用の最適化 | SRE / プラットフォームエンジニア |
| **第4層** AI最前線 | 高度な実務・専門が必須 | プロダクトエンジニア / MLエンジニア / データサイエンティスト / MLOps / AIエージェント・アプライドAI / フォワードデプロイド（FDE） |

### 自分向けの読み（現職 × 学習中）

現職は実機評価・ECU計測。並行して Web / Python・自動化 / Linux / AIエージェント協働を伸ばしている前提で、動画の層を次のように翻訳する。

| 層 | 自分への効き |
|----|----------------|
| 第1層 | すでに Web（フロント寄り）と Linux（インフラ入口）を学習中。**未経験スタート＝第1層**という動画の指針は、ポートフォリオと計測自動化の土台づくりと一致 |
| 第2層 | 計測ログ整形・パイプライン化は **データエンジニア寄り**。評価の再現性・自動化は **QA/SET 的な品質の仕組み化**。社内への AI 導入・業務変革は **コーポレートIT/DX** の視点とも重なる |
| 第3層 | 基盤・信頼性の専門は先。まずは自分のツール／スクリプトが「落ちない・説明できる」レベルを第1〜2層で固める |
| 第4層 | いまの興味に近いのは **AIエージェント・アプライドAI** と、課題定義まで持つ **プロダクトエンジニア** 視点。個人事業寄りの「現場に入って一気通貫」は **FDE** のイメージに近い。ML/DS は数学・大規模開発が前提なので、当面は深追いしない |

## 現職中の優先（前回メモと共通）

1. **給料分の成果をちゃんと出す** — 学習や職種マップ眺めが成果を削らない
2. **実務とスキル習得をなるべく兼ねる** — 計測・評価の改善がそのまま第1〜2層のスキルになるようにする

両立できないときは目標1を優先する。

## 職種ごとのメモ（自分が触る範囲だけ）

全部を追わない。**いまの成果か、個人事業の行き先に効くもの**だけ残す。

| 職種（層） | いまの自分との接点 | 次に試す／意識すること |
|------------|--------------------|------------------------|
| フロントエンド（1） | ポートフォリオ・レポートUI | 「見た人がすぐ状況把握できるUI」を計測まわりに小さく載せる |
| バックエンド（1） | まだ浅い | データ保存・API が必要になったときだけ足を踏み込む（先に作りすぎない） |
| インフラ・クラウド（1） | Linux 学習中 | 自分の自動化を再現可能な環境で動かす（ローカル→簡単なクラウドは余裕があれば） |
| データエンジニア（2） | Python / pandas / ログ整形 | DWH 用語は知っておく程度。まず **綺麗な計測データの作り方** を実務で回す |
| QA・SET（2） | 良否判定・再現手順 | 手動テストの列挙ではなく、**同じ手順で繰り返せる仕組み**としてスクリプト化する |
| 社内SE・コーポレートIT（2） | AIエージェント導入の安全な使い方 | 現場で使う AI の境界（秘密情報・誤操作）を自分用ルールにしておく |
| プロダクトエンジニア（4） | 「なぜ測るか・何を残すか」 | 実装速度が上がるほど、**何を作らないか**の判断が成果になる |
| AIエージェント・アプライドAI（4） | 学習サイクルへの AI 組み込み | 制御・ハーネス・プロンプト注入対策など「本番で壊れない使い方」の用語を少しずつ拾う |
| FDE（4） | 個人事業の将来像 | 顧客課題→実装→業務改善の一気通貫。今は現職の課題解決を小さく真似る |

## 運用の目安
