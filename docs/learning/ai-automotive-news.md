# 学習メモ: AI × 自動車関連技術のニュース収集

> 2026-07-31 の覚書を、学習方針として残したもの。公開サイト本文ではなく **自分用の収集・勉強メモ**。

## 覚書（原文の意図）

AIニュースを追うとき、**AIを活用した自動車関連技術**も収集して勉強したい。

- **ロードマップ上の行き先**: 個人事業主に向けた関連スキルの習得
- **いま学ぶ理由**: 現職の期間でもスキル向上は必要。より良い仕事をしながらスキルを習得したい

### 現職中の目標（優先順）

1. **給料分の成果をちゃんと出す** — 本業の責任を先に果たす。学習や情報収集が成果を削らない
2. **実務とスキル習得をなるべく兼ねる** — 仕事で使う範囲で学び、仕事の改善がそのままスキルになるようにする

学習は「成果のあとに余力で」ではなく、**成果を出すための手段として実務に載せる**。両立できないときは目標1を優先する。

## なぜ現職中に自動車×AIも追うか

| 時間軸 | 学びの使い方 |
|--------|----------------|
| いま（現職） | 実機評価・ECU計測などの仕事に効く知識を取り込み、給料分の成果（精度・説明力・再現性・効率化）に直結させる |
| 先（個人事業） | AIエージェント協働・データ処理・自動化・情報収集の仕組み化。制作物や発信のネタにもなる |

現場経験（整備・ECU計測・実機評価）がある前提で、ニュースを「用語を知る」だけで終わらせず、**いまの成果に効く形へ翻訳し、実務の中で小さく試す**と定着しやすい。

## 収集の軸（タグ案）

1件あたり、可能なら次をメモする。

| タグ | 例 |
|------|-----|
| `adas` / `autonomous` | 認識・予測・制御、センサフュージョン |
| `sdv` / `ecu` | ソフトウェア定義車両、OTA、車載ソフトウェア |
| `edge-ai` | 車載推論、組み込みML、NPU |
| `simulation` | シナリオ評価、デジタルツイン、HIL/SIL 周辺 |
| `diagnostics` | 予知保全、異常検知、ログ解析 |
| `tooling` | 個人事業にも転用できるAI開発・自動化ツール |
| `career` | スキル・資格・市場の話（収集しすぎない） |

毎回「成果にどう効くか」を先に1行書き、続けて「実務の中で何を試せるか（スキル兼ね）」を書く。個人事業側の転用は余裕があれば。

## メモの型（短く）

```text
日付:
見出し / 出典:
一言要約:
成果への効き: （計測・評価・ECU・現場のどれを良くできるか。なければ「なし」→深追いしない）
実務で兼ねる学び: （自動化・Python・AI協働など、仕事の中で触れる形）
次に試すこと: （任意・小さく。本業の成果に載るもの優先）
```

## 運用の目安

- 週に数件でよい。網羅より **成果への翻訳と、実務に載る小さな試し** を優先する
- 成果に効かない話題はタグだけ残して深追いしない（目標1を守る）
- 一般AIニュースと自動車×AIは同じストックでよい（タグで分ける）
- 将来、自動収集（RSS / YouTube 等）にする場合は `projects/youtube-dashboard/` の「取得 → 静的HTML / 通知」パターンを参考にする。まずは手メモで軸が固まってからで十分
