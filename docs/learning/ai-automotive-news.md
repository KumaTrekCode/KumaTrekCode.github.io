# 学習メモ: AI × 自動車関連技術のニュース収集

> 2026-07-31 の覚書を、学習方針として残したもの。公開サイト本文ではなく **自分用の収集・勉強メモ**。

## 覚書（原文の意図）

AIニュースを追うとき、**AIを活用した自動車関連技術**も収集して勉強したい。

- **主目的（ロードマップ）**: 個人事業主に向けた関連スキルの習得
- **副次的な価値**: 現職（実機評価・ECU計測など）にも役立つ情報を学ぶことにも意味がある

両方を対立させず、**同じインプットを二つの出口に振る**方針でよい。

## なぜ両方やるか

| 出口 | 学びの使い方 |
|------|----------------|
| 個人事業向け | AIエージェント協働・データ処理・自動化・情報収集の仕組み化。制作物や発信のネタにもなる |
| 現職向け | ADAS / 自動運転周辺、車載AI、計測・診断・予知保全、シミュレーション、ECU・ソフトウェア定義車両（SDV）の動向把握 |

現場経験（整備・ECU計測・実機評価）がある前提で、ニュースを「用語を知る」だけで終わらせず、**自分の計測・評価の言葉に翻訳する**と定着しやすい。

## 収集の軸（タグ案）

1件あたり、可能なら次をメモする。

| タグ | 例 |
|------|-----|
| `adas` / `autonomous` | 認識・予測・制御、センサフュージョン |
| `sdv` / `ecu` | ソフトウェア定義車両、OTA、車載ソフトウェア |
| `edge-ai` | 車載推論、組み込みML、NPU |
| `simulation` | シナリオ評価、デジタルツイン、HIL/SIL 周辺 |
| `diagnostics` | 予知保全、異常検知、ログ解析 |
| `tooling` | 個人事業にも転用できるAI開発・自動化ツール |
| `career` | スキル・資格・市場の話（収集しすぎない） |

主目的が個人事業スキルなら、毎回 `tooling` か「自分なら何を試作できるか」を1行書く。

## メモの型（短く）

```text
日付:
見出し / 出典:
一言要約:
現職への示唆: （計測・評価・ECU・現場のどれに効くか。なければ「なし」）
個人事業への示唆: （自動化・Python・AI協働・制作物のどれに効くか）
次に試すこと: （任意・小さく）
```

## 運用の目安

- 週に数件でよい。網羅より **翻訳（自分の言葉）と次アクション** を優先する
- 一般AIニュースと自動車×AIは同じストックでよい（タグで分ける）
- 将来、自動収集（RSS / YouTube 等）にする場合は `projects/youtube-dashboard/` の「取得 → 静的HTML / 通知」パターンを参考にする。まずは手メモで軸が固まってからで十分
