# ハーネスとループ（このリポジトリ向け）

提示された「タスク取得 → 実装 → 検証 → 自己修正 → PR → 人間がマージ」を、**静的 GitHub Pages 用リポジトリ**に合わせた形で回すための説明。

## このリポジトリですでに強い部分

| 部品 | 実態 |
|------|------|
| 一発チェック（ハーネス） | `npm run check`（sync / 画像アイコン / html-validate / OG / smoke / ESLint / links / a11y / audit） |
| CI | `.github/workflows/ci.yml` が PR と main で同じ `npm run check` |
| ローカル抑止 | `pre-push` でも `npm run check` |
| 運用手順 | [WORKFLOW.md](./WORKFLOW.md) |

足りなかったのは **エージェント契約** と **拾えるタスクキュー** と **次タスク取得**。それを次で足す。

## 全体像

```text
[Knowledge] docs/learning/*     … 動画・覚書の蓄積・キャリア壁打ち（人間＋壁打ちAI）
[Ideas]     docs/ideas/*        … プロダクト／アプリ案の記録（実装しない。正本のみ）
      │
      │ 必要なときだけ「サイトへ載せる／ツール化する」を切り出す（ideas は人間が方針決定後）
      ▼
[Queue]     ROADMAP.md          … 実装可能・検証可能なタスクだけ
      │
      │  npm run task:next
      ▼
[Loop]      実装 → npm run check → 失敗ならログを読んで再修正（最大目安3回）
      │
      ▼
[PR]        エージェントが PR 作成
      │
      ▼
[Human]     レビューしてマージ（ここだけ人間必須）
```

## 具体的にどう動くか

1. **タスクの自動取得**  
   ループ開始時に `npm run task:next` を実行する。`ROADMAP.md` の **Agent queue** から、最初の `- [ ] \`id\`: …` を1件返す。  
   （将来 Issue 連携したくなったら、同じ出力形に寄せればよい。最初はファイル1枚で十分。）

2. **実装と検証の自動ループ**  
   AI がコード／ドキュメントを変更する → `npm run check` → 失敗したらエラーログを読んで修正 → 再実行。  
   人間を呼ばないのは「チェックが機械判定できる間」だけ。仕様が曖昧なら PR に質問を書いて止める。

3. **成果物の提出**  
   チェック成功後、ブランチを push して PR を作る。該当タスクを `[x]` にする。

4. **Human on the Loop**  
   マージ判断・本番（GitHub Pages）への反映は人間。エージェントは main 直 push しない。

## Knowledge / Ideas とビルドループを混ぜない

| | Knowledge（学習） | Ideas（案） | Build loop（実装） |
|--|-------------------|-------------|---------------------|
| 置き場 | `docs/learning/` | `docs/ideas/` | `ROADMAP.md` |
| 例 | FIRE 動画の要点、職種マップ | 新規アプリ案のメモ | README 導線、sync allowlist、a11y 修正 |
| 完了条件 | 壁打ちで方針が残る | 正本に記録された | `npm run check` が通る |
| エージェント | 参照・壁打ちは可。チェックボックスを勝手に消化しない | **記録のみ。勝手に実装・ROADMAP 昇格しない** | 1 タスクだけ実装して PR |

学習メモの「計測自動化を1本」は **仕事の成果** であり、必ずしもこの repo の Agent queue ではない。サイトや `tools/` に落とすときだけ ROADMAP に切り出す。アプリ案（`docs/ideas/`）も同様で、**人間が完了条件つきで ROADMAP に昇格するまで実装しない**。

### 切り出し運用（フォルダは動かさない）

「切り出し」は `docs/learning/` の物理移動ではなく、**タスクの昇格**だけを指す。

1. **人間**が learning / roadmap-wall を見ながら、サイト HTML・`tools/`・公開導線など **`npm run check` で検証できる成果**だけを選ぶ
2. Backlog または Agent queue に `- [ ] \`task-id\`: …（完了条件: …）` で書く
3. **エージェント**は Agent queue の1件だけ実装する。learning 内のチェックボックスを実装タスクとして消化・完了扱いにしない
4. キャリア・実務・壁打ちメモは learning に残す（公開サイト本文にしない）

昇格候補が無いときはキューを増やさない。フォルダ構成は現状維持でよい。

## ローカルでループを体感する（おすすめの最初の一手）

```bash
npm run task:next
# 表示された1タスクだけをエージェントに依頼する例:
# 「ROADMAP の次タスクだけ実装し、npm run check が通るまで自分で直して PR まで」
```

契約の要約はリポジトリ直下の [AGENTS.md](../AGENTS.md)。

## 次に足すなら（まだやらないこと）

- Issue 自動起票・自動アサイン（キューがファイルで回るうちは不要）
- チェック全失敗時の自動コメント Bot（まず手元ループで十分なことが多い）
- 学習メモ全件の自動実装（知識と実装の境界が壊れる）
